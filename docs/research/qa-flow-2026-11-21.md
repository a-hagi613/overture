# QA flow audit, 2026-11-21 (issue #302, Audit A)

Walked the app as a brand-new user on the e2e stack (fresh database, test mode, Playwright):
sign in, Resume (PDF), Your facts, What you want, then Home, Ready, Board, Review, Inbox,
Notifications, Profile, Settings, Search. No console errors and no 4xx/5xx on any route.
Horizontal overflow is zero at 1280 on every route (Audit B covers the other widths).

Not walked, and why: sending an approval needs a recorded ATS flow and a queued application,
which a new user does not have. The approval path has its own e2e (`approval.test.ts`); this
audit did not exercise it. Prod was not touched.

## Fixed in this PR

### F1. Facts step: "0 of 0 answered", no field for work authorization, salary or self-ID

- Route: `/onboarding/facts`, any user who has not saved Targets yet (every new user).
- Root cause: `onboarding-step.ts` builds the country rows from the saved Targets' locations and
  the currency rows from queued applications, saved answers and the Targets salary currency. The
  Facts step (3) comes before What you want (4), so a new user has none of them: zero countries,
  zero currencies, so no row to answer. Every existing onboarding e2e calls
  `PUT /api/profile/targets` before opening Facts, which is why CI never saw it. It is not a
  prod-data gap; no seed is missing.
- Fix: with no countries known, use the resume's `current_country`, else the three countries with
  the most open Postings. With no currencies known, use the currency of those countries.
- Guard: `test/e2e/onboarding-full.test.ts` fails on main at "0 of 0 answered" and passes now.

## Open: onboarding

### O1. There is no step 5 (Forwarding, consent, Start). Blocker. Ticket #217 is open and unbuilt.

- Route: `/onboarding/targets`, Continue.
- Expected (SPEC §onboarding): step 5 with the forwarding address, filter guide, consent and Start.
- Actual: Continue records step 4 and navigates to `/profile#profile-targets`. No route
  `/onboarding/forwarding` exists. `onboarded_at` is only set by `POST /api/onboarding/5`, which
  nothing in the UI calls, so `needsOnboarding` stays true and `pause_reason` stays `onboarding`.
  A user can press Start on Board or Home, but the consent version is never recorded.
- Cause: #217 is not done (blocked by #216, #212, #214, #204).
- The e2e therefore ends at step 5 reached (`/api/onboarding` says 5), not at "onboarding complete".
  Extend it when #217 lands.

### O2. "What you want" blank in prod: not reproduced

- Route: `/onboarding/targets`.
- Local result: renders with chips and count for a new user, with or without seeded postings.
- Guesses, in order: (1) `GET /api/onboarding/targets` is slow on the prod-sized catalog
  (`targetChoices` runs five grouped scans of `postings` and `posting_tags` per request) and the
  page renders an empty string while pending, with no skeleton or timeout; (2) prod roles or
  locations choices come back empty because prod postings lack role tags. Needs the prod response
  time and body of that endpoint; only the orchestrator should fetch it.
- Cheap hardening worth a ticket: show a skeleton while pending, and cache the choices.

### O3. Step label differs between steps

- Steps 1, 2 and 4 say "Forwarding & start"; Facts says "Address & start"
  (`copy.onboarding.factsStepLabels`). Same step, two names.

## Open: rest of the app, ranked

1. **Sidebar badges are sample data (P1).** Every route for a user with zero applications shows
   "Ready 2", "Review 4", "Inbox 3" (`copy.sample.*` in `side-nav.tsx`). Real counts are never
   shown, and a new user is told there is work waiting. Fix: wire the badges to the real counts or
   hide them at zero.
2. **Inbox is a placeholder (P1).** `/inbox` shows "Coming in a later slice / Replies from
   employers would land here." The sidebar links to it with a badge. Hide the entry until the
   Inbox ticket ships, or build it.
3. **Home and sidebar show "0 of 0 on your week plan" (P2).** A user with no grant sees 0 of 0
   with no explanation. Expected: a line telling them the plan starts at Start or after an admin
   grant.
4. **`/board` has no sidebar (P2).** The shell nav is missing there; the other routes have it. If
   deliberate (board canvas), there is still no way back except the browser. Audit B should
   confirm against the canvas.
5. **Profile card and onboarding disagree on completeness (P2).** After step 4 the user lands on
   Profile with "Auto-apply paused: Setup isn't finished" and the only way out is O1.

## Method

- `test/e2e/onboarding-full.test.ts`: the real UI, seeded Postings only.
- A throwaway probe (not committed) visited each route and recorded visible text, page errors,
  response codes >= 400 and `scrollWidth`.
- The test uses the existing `resume-text.pdf` fixture rather than generating a PDF, so the
  recorded resume parse still applies.
