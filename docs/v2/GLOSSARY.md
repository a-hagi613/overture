# Overture v2 glossary

The words, used exactly. Updated 2026-11-19 for Session 4. The banned words (end of file) never appear in anything a user can read; code may use them for internals (`SPEC.md`, Words rule).

## Language

**Posting**:
A job opening published by an employer on an ATS.

**Application**:
One attempt to apply to one Posting on the user's behalf, from preparation to the employer's final answer.

**Stage**:
Where an Application stands with the employer, shown as a Board column: Queued, Applied, Screening, Interviewing, Offer, Closed.

**Status**:
Where an Application stands inside Overture: preparing, needs review, ready, sending, confirming, sent, couldn't apply (failed), skipped, withdrawn. Separate from Stage.

**Queued**:
The first Stage: being prepared, waiting on a Review, waiting for its time to send, or being confirmed with the employer.

**Review**:
A factual question Overture will not guess at and needs the user to answer before some Applications can be sent. Answering it once unlocks every Application that asks it.
_Avoid_: Hold, review item, CAPTCHA review

**Confirming**:
The Status after Submit was clicked but before the employer's confirmation was seen. Overture waits up to 24 hours for an acknowledgement email and never sends it again. Shown as "Checking with the employer".

**Couldn't apply**:
An Application that was not sent after its tries (for example the site blocked it), or one whose submission could not be confirmed. It never uses one of the user's applications.

**Applications left**:
How many more Applications the user's plan allows; one is used only when an Application is actually sent.
_Avoid_: credit, allowance (in user-facing copy)

**Match score**:
0–100 fit between a Posting and the user's resume and targets, with a one-line reason. "Strong match" at 80 or above.

**Check-in**:
A one-tap prompt on Home asking what happened with an Application that has been in Applied for 21 days with no employer email.

**Fact**:
Something true about the user that answers application questions (work authorization, notice period). Factual answers come only from Facts.

**Question catalog**:
Every application question Overture has seen, shared across all users without their answers, each linked to the Fact that answers it.

**Job-search address**:
The address Overture gives each user on mail.tryoverture.com for their applications; employers reply to it, and the user reads and replies in Inbox.
It is the email typed on every application form; the user's personal email is used only to sign in and for Overture's own notices.
_Avoid_: alias, real-email mode (retired)

**Needs you**:
The red pill on anything waiting for the user: an open Review, or a Queued card blocked by one.

**Fact**, **Facts by tier**: Tier 1 asked in onboarding, Tier 2 "Strengthen your profile", Tier 3 learned from Reviews.
_Avoid_: Answer Bank, Memory Base, saved answers as a place (the source chip "From your saved answers" stays)

## Banned in anything a user can read

`Hold` (as a stage or a question), runner, lease, provider, dispatch, attempt, ledger, credit, CAPTCHA, Brain, Hands,
workspace, Job Board (it is "Board"), Answer Bank, Memory Base, Live Tab.
